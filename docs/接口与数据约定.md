# 接口与数据约定

## 公开盘口

快照包含`started_at`实际抓取开始、`fetched_at`实际抓取结束、`markets`市场原件、`books`订单簿、`fees`费用原件、`errors`实际失败及`requests`请求记录。

`markets`按市场标识索引，每项包含`gamma`平台原件和`clob`订单簿市场状态。`books`按结果代币索引。`fees`按市场标识索引，保留接口返回的条件标识、完整代币表及费用参数。

```python
from pm_paper import PublicClient

client = PublicClient()
snapshot = client.snapshot(["实际市场标识"])
```

实际时间使用带时区的标准时间字符串。目录参考价格和执行盘口分别保存。执行账本沿用源代码的300秒报价与盘口检查，费用函数当前接受指数为1的接口形式，费用公式为份额乘费率乘价格乘一减价格。

## 决定

顶层字段`decision_id`为本次决定标识，`created_at`为真实创建时刻，`policy_version`为所属项目实际政策版本，`items`为逐项动作。

每项包含以下字段。

| 字段 | 含义 |
|---|---|
| market_id、event_id | 市场及事件标识 |
| title、condition_id、token_id、outcome | 标题、条件、结果代币及结果名 |
| action | BUY买入、SELL卖出、WATCH观察或HOLD持有 |
| reason、support、counterevidence | 判断理由、支持与最强反证 |
| sources | 资料引用数组 |
| probability | 数值概率，未知为null |
| rules_text、rules_hash | 冻结的完整规则正文及摘要 |
| budget、limit_price | 买入含费预算及每份限价 |
| quantity、limit_price | 卖出份额及每份限价 |

金额、数量和价格使用十进制数字字符串。周期生成器从公开市场原件绑定身份和规则，数值概率附`probability_method`方法说明。调用方直接使用账本时按相同约定组织原件。

```python
from pm_paper import PaperAccount

account = PaperAccount("runtime/account.sqlite")
try:
    receipt = account.freeze(decision)
    snapshot = client.snapshot([item["market_id"] for item in decision["items"]])
    execution = account.execute(decision["decision_id"], snapshot)
finally:
    account.close()
```

已有决定执行返回原回执。新的判断使用新的决定标识和真实时间，原历史继续保留。

## 独立预检

`preflight(item, snapshot, cash=None)`供任何记账实现使用，返回`status`可行状态、`filled`份额、`cost`含费成本、`minimum_cost`最低份额所需金额、`exit_net`退出净收入、`unable_to_exit`无法退出份额、`immediate_exit_loss`立即退出损失率及`reasons`原因。

买入预检按实际可买份额计算退出。卖出预检返回挂单可成交量，已有持仓数量由所属账本核对。实际执行仍需要所属账本冻结决定后的新报价。

## 代理协议

代理提供`run(role, task, context, directory)`方法，返回一个结构化对象。`role`为角色，`task`为具体任务，`context`为实际上下文，`directory`为本次交付目录。

模型适配器采用兼容的Chat Completions消息格式，保存最终可见答复、响应标识、模型和用量。返回被截断、格式错误或请求失败时，原交付和错误进入对应目录。

研究与最终汇总输出`items`动作数组，资料与复核分别按自己的提示词输出事实、问题和补查。调用方的原生代理可通过Python或命令行按相同协议接续。

## 报告

`cash`为现金，`realized_pnl`为已实现盈亏，`unrealized_pnl`为完整估值下的未实现盈亏，`equity`为已知报价条件下的可退出净值。`known_exit_equity`与`exit_value_known`保留可退出的已知部分，`unknown_valuation_markets`和`unknown_valuation_quantity`说明未知部分，`known_unfilled_total`说明已知买盘不足份额。

存在未知或残余份额时，读取各字段的实际状态及仓位明细。正式结算增加兑付和对应已实现盈亏，行情估值保留其原时点。
