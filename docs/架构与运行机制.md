# 架构与运行机制

## 模块职责

| 模块 | 输入 | 输出及责任 |
|---|---|---|
| public.py | 事件范围或市场标识 | 公开规则、平台与订单簿状态、费用、两面挂单和逐次请求 |
| screening.py | 带真实时间的目录 | 逐市场去向、事件合并、代表市场及轮转顺序 |
| agents.py | 角色、任务、上下文和服务配置 | 原请求、可见答复、结构化交付、用量及实际错误 |
| prompts/ | 项目目标与角色职责 | 可迁移的项目接管、研究、资料、反方及复盘提示 |
| execution.py | 具体动作、真实报价及可选现金 | 独立预检及含费退出核算，可由其他账本调用 |
| fills.py | 盘口、金额或份额、费率和限价 | 逐档成交、费用、净收入及未成交份额 |
| account.py | 冻结决定和后取报价 | 事务化账户、持仓、执行防重、正式结果与报告 |
| workflow.py | 配置、目录、资料、运行目录及可选账户 | 一个完整周期及逐阶段原件 |
| cli.py | 显式参数和文件 | 统一的命令行入口 |

## 周期中的信息流

周期先处理已有持仓，再读取本轮目录和既往选择记录。目录筛选按事件安排研究，保留常规、专项、待补查和暂停状态。分析盘口按参考金额核算两面成本，连同完整市场规则及调用方资料交给研究负责人。

同一运行目录使用操作系统文件锁控制周期重叠，其他项目可使用各自的运行目录。锁在周期完成或失败后释放。

默认由研究负责人提出动作，反方复核指出有证据的问题，项目判断汇总核验意见后形成最终结构化动作。模型服务可以相同或分别配置，调用方也可以自行组织角色。

程序从本轮市场原件绑定事件、市场、条件、结果代币及规则正文，对模型输出做结构检查。执行阶段先冻结决定，再读取执行报价。字段、身份、费用、时间、限价、最小数量、实际深度和现金分别检查。未成交与部分成交进入实际执行结果。

模型调用或新增资料失败时，周期保存实际错误，并继续已有持仓的正式结果检查及估值输出。周期清单保存真实开始、结束、覆盖市场、无效项目和完整执行路径。

## 资料和交付共享

每次代理调用使用独立目录，保存request.json请求、response.json可见答复及调用信息、result.json结构化交付和error.json实际错误。已有请求目录用于读取原任务，新调用使用新的任务目录。

`--evidence`接收调用方整理的结构化资料数组。每项应携带事件、来源、来源自身日期、实际取得时刻、原文引用和核验状态。相同原文可以作为多个事件或领域的引用，新的判断保留自己的信息截止和引用版本。

资料工具由调用方接入。具有浏览、检索或文件工具的原生代理可直接使用资料助手提示词，再按相同格式交付。模型接口适配器处理消息调用，实际工具能力依所属代理运行环境提供。

## 账户与一致性

`PaperAccount`是从现有执行代码提取的持久账本。SQLite是本地数据库格式，写入使用立即事务，逐项执行使用保存点。决定、执行、流水及已消费盘口都有各自的防重依据。读写失败时保留原已提交历史，部分项目失败按真实项目记录。

同一决定标识的内容摘要固定，重复执行返回原结果。盘口消费标识绑定源端时刻、代币、方向和价量，控制同账户重复使用同一挂单深度的模拟成交。

追加买入核对已有持仓与本次决定的规则正文和摘要。规则版本变化会形成明确的未成交原因，由研究负责人复核原持仓后单独处理，原冻结决定及其依据继续可追溯。

已有其他格式的账户可使用`preflight`和`fills`接口，按所属账本自己的事务保存决定和执行结果。当前兼容账户通过应用标识检查格式，默认加载要求文件已存在。

## 结果和迭代

报告分开记录现金、已实现盈亏、未实现盈亏、已知可退出金额、无法退出份额和估值未知。估值保留真实行情时点。正式结算引用平台和订单簿服务的明确结果，退款或均分按待核验状态保留。

研究评价按事件、信息截止、完整规则、方法版本和正式结果组织。分档、重复更新和相关市场保存其关系。复盘角色提取具体经验，重要方法变化采用真实时间和未来比较条件。当前框架提供执行与留档路径，预测方法由项目按资料和目标接入。

## 日程接入

使用操作系统日程或代理平台日程调用`cycle`，每次保留独立周期目录。资料收集与深入分析可以分别调用对应角色，并根据项目频率错开。启动前核对所属账户和在途任务，处理相同事项时接续原任务和原决定标识。
